# Lazo MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir Lazo (listas de regalos en familia con sorpresa garantizada) hasta una v0.x usable: núcleo, interfaz, demo pública, servidor PocketBase y APK.

**Architecture:** Cliente React con un núcleo puro (`src/core`) y una interfaz `Api` con dos implementaciones (PocketBase y demo en memoria). Servidor: PocketBase (migraciones JS, reglas y `pb_hooks`) más un servicio Node `unfurl` en la red interna de Docker. El sorteo se compila desde `src/core/draw.ts` para los hooks.

**Tech Stack:** React 19, Vite 8, TypeScript 6, Vitest 4, Playwright, Capacitor 8, pocketbase (SDK JS), SheetJS (carga diferida), Zod 4, Node 24 (unfurl), PocketBase 0.3x, Caddy 2.

**Spec:** `docs/superpowers/specs/2026-11-11-lazo-design.md`

## Global Constraints

- npm, Vite, Vitest y Playwright se ejecutan en WSL (`~/.local/node`). Smart App Control bloquea rolldown en Windows.
- Dinero siempre en céntimos enteros (`Cents = number`); se formatea con `Intl.NumberFormat('es-ES')`.
- Ningún registro de `items` lleva estado; el estado se deriva de `claims` y `contributions`.
- `puedeVerEstado(viewer, list) = list.user !== viewer` (las listas de niños, sin `user`, son visibles para todos).
- Hay un único componente de botón: `src/ui/Button.tsx`. Prohibido escribir `<button className=…>` fuera de él.
- Todos los textos de la interfaz, en español.
- IA gratuita por defecto (Gemini); Claude, opcional y de pago. Las claves solo en el dispositivo.
- Invitación: 14 días y 30 usos por defecto; token de 128 bits; se guarda su SHA-256.
- `unfurl`: http y https, puertos 80 y 443, 3 redirecciones, 6 s, 1,5 MB, solo `text/html`.
- Cada versión: CHANGELOG (Keep a Changelog), tag `vX.Y.Z` y GitHub Release.
- CI con `concurrency` (cancel-in-progress) y caché de npm.

## Review Focus

1. Lista propia vista a través de `expand` o de un filtro de la API de PocketBase → no devuelve ninguna reserva (prueba de reglas, Task 7).
2. Excel con cabeceras raras, celdas vacías, precios «12,50 €» o filas en blanco → la vista previa ignora las vacías y convierte los precios (Task 2).
3. Sorteo imposible (2 personas que se excluyen entre sí) → error explicativo, sin bucle infinito (Task 1).
4. URL de una tienda que redirige a `http://127.0.0.1` o a `169.254.169.254` → se rechaza (Task 6).
5. Regalo a medias con aportaciones que superan el precio, o un precio desconocido → el estado es «Cubierto» o «Sin precio» y no da porcentajes absurdos (Task 1).

### Task 1: Núcleo de dominio

**Files:** Create `src/core/{types,money,visibility,split,draw,status}.ts` · Test `test/core/*.test.ts`

**Interfaces (produce):**
- `types.ts`: `Id`, `Cents`, `Occasion`, `User`, `Group`, `Membership`, `GiftList {id, group, name, user?: Id, managers: Id[], birthYear?}`, `Item`, `Claim {id, item, user, status: 'reserved'|'bought', units}`, `Contribution {id, item, user, amountCents, paid}`, `Draw`, `Assignment`.
- `money.ts`: `parseAmount(input: string): Cents | null`, `formatMoney(c: Cents, currency?: string): string` (adaptado de Repartito).
- `visibility.ts`: `canSeeStatus(viewer: Id, list: GiftList): boolean`.
- `split.ts`: `byWeights(amount: Cents, weights: Record<Id, number>): Record<Id, Cents>` (mayor resto, como en Repartito), `equalShares(amount, ids)`, `settle(buyer: Id, contributions: Contribution[]): {from: Id, to: Id, amount: Cents}[]`.
- `status.ts`: `itemStatus(item, claims, contributions): {kind: 'free'|'reserved'|'bought'|'partial'|'covered', unitsLeft: number, percent?: number, by: Id[]}`. Sin precio + aportaciones → `partial` sin `percent`.
- `draw.ts`: `drawPairs(ids: Id[], exclusions: [Id, Id][], rand: () => number): Map<Id, Id>`; lanza `DrawImpossible` con un `reason`. Retroceso con un tope de 10 000 pasos.

- [ ] Tests:
  - `canSeeStatus` es falso para el dueño y verdadero para la lista de un niño;
  - `byWeights(1000, {a:1, b:1, c:1})` suma 1000 y da `{a:334, b:333, c:333}`;
  - `drawPairs` con 200 semillas: nadie se regala a sí mismo y se respetan las exclusiones;
  - `[a,b]` con la exclusión `a-b` → `DrawImpossible`;
  - `itemStatus`: libre, reservado, comprado, aportaciones al 60 %, por encima del 100 % → `covered`, y sin precio.
- [ ] Implementar, poner los tests en verde y commit.

### Task 3: Api y DemoApi

**Files:** Create `src/api/types.ts`, `src/api/demo.ts`, `src/api/seed.ts` · Test `test/api/demo.test.ts`

**Interfaces:** `interface Api { me(); groups(); group(id); lists(groupId); items(listId); claims(listId); contributions(listId); addItem; updateItem; deleteItem; claim(itemId, status); release(claimId); contribute(itemId, cents); createGroup; createInvite(groupId): {url}; join(token, name); runDraw(groupId, exclusions, budget); myAssignment(groupId); unfurl(url); myPurchases() }`.

Una regla: `DemoApi.claims(listId)` devuelve `[]` si `!canSeeStatus`. Así la demo se comporta igual que el servidor. `DemoApi.setViewer(id)` sirve para «Ver como…». El seed, la familia Robles en Navidad 2026, tiene 6 personas, una lista de niña (Vera, 6 años), unos 20 regalos, reservas, un regalo a medias y un sorteo.

- [ ] Test: viendo como dueño de una lista, `claims` está vacío y, como otra persona, no. Implementar y commit.

### Task 6: Servicio unfurl

**Files:** `server/unfurl/{index.mjs,guard.mjs,meta.mjs}`, `server/unfurl/test/*.test.mjs`, `server/unfurl/Dockerfile`

- `isBlockedIp(ip: string): boolean`: IPv4 privadas, loopback, 0/8, 100.64/10, 169.254/16, 224/4, 240/4, ::1, fc00::/7, fe80::/10 y ::ffff:mapeadas.
- `safeFetch(url)`: `http.request` con un `lookup` que comprueba la IP, redirecciones manuales (como mucho 3) y vuelta a comprobar en cada una, tiempo límite y tope de bytes.
- `meta.mjs` lo genera esbuild a partir de `src/core/meta.ts` y `amazon.ts`.
- [ ] Tests: IP bloqueadas, un servidor local de prueba que redirige a 127.0.0.1 (se rechaza) y respuestas de más de 1,5 MB (cortadas). Commit.
